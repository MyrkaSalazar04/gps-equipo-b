## 1. ¿Qué Es Una Matriz RACI?

RACI es un acrónimo que define el rol de cada persona en cada actividad:

- **R** = **Responsable** (quien ejecuta la tarea)
- **A** = **Aprueba** (quien autoriza y responde por el resultado final)
- **C** = **Consultado** (quien aporta información antes de decidir)
- **I** = **Informado** (quien recibe notificación después de la decisión)

> **Regla:** cada actividad debe tener **un solo A** y **al menos un R**.

## 3. Plan de Comunicación

### 3.1 Canales y Frecuencia

| Tipo de comunicación | Audiencia | Canal | Frecuencia | Responsable |
|---|---|---|---|---|
| Reunión de avance | Cliente + Director | Videollamada / presencial | Semanal (viernes) | Director |
| Reporte de estatus | Cliente | Correo electrónico | Quincenal | Director |
| Demo del sistema | Cliente + usuarios clave | Presencial / remoto | Al cierre de cada fase | Director |
| Actualización de Issues | Equipo interno | GitHub Projects | Continuo | Director |
| Consulta jurídica | Área jurídica | Correo / reunión | Según se requiera | Director |
| Capacitación | Usuarios finales | Presencial | Una sesión por rol | Director |
| Comunicación de crisis | Cliente + Director | Llamada telefónica | Inmediata | Director |

### 3.2 Reuniones Programadas

| Reunión | Día | Duración | Agenda |
|---|---|---|---|
| Daily (auto-seguimiento) | Lunes | 15 min | Revisar Issues de la semana |
| Revisión con cliente | Viernes | 30 min | Avances, bloqueos, riesgos |
| Revisión de fase | Al cierre | 1 hora | Entrega de entregables de la fase |

### 3.3 Herramientas

| Herramienta | Uso |
|---|---|
| **GitHub Issues** | Registro y seguimiento de tareas |
| **GitHub Projects** | Tablero Kanban del proyecto |
| **GitHub Pull Requests** | Revisión y aprobación de cambios |
| **Correo electrónico** | Comunicación formal con el cliente |
| **Videollamada** | Reuniones semanales |
| **Repositorio Git** | Control de versiones y evidencias |

## 4. Escalamiento de Problemas

Si surge un bloqueo, el flujo de escalamiento es:

1. **Nivel 1:** El Director de Proyecto intenta resolverlo en 24 horas.
2. **Nivel 2:** Se notifica al cliente y se documenta en GitHub Issues.
3. **Nivel 3:** Se convoca reunión extraordinaria con el cliente y el área jurídica (si aplica).
4. **Nivel 4:** Se activa la reserva de contingencia si es un problema técnico o legal mayor.
